# Contributing to AgentCall

Thank you for considering contributing to AgentCall! We welcome contributions from everyone.

## Code of Conduct

All contributors must adhere to our [Code of Conduct](./CODE_OF_CONDUCT.md).

## How to Contribute

### Reporting Bugs

1. Check existing issues to avoid duplicates
2. Use the bug report template
3. Include: steps to reproduce, expected behavior, actual behavior, environment details

### Suggesting Features

1. Check existing issues and discussions
2. Use the feature request template
3. Explain the use case and how it aligns with PRODUCT_VISION.md

### Pull Requests

1. Fork the repository
2. Create a feature branch (`feat/your-feature-name`)
3. Follow the development guide in [DEVELOPMENT_GUIDE.md](./DEVELOPMENT_GUIDE.md)
4. Run tests and lint locally
5. Submit a PR against the `develop` branch

## Development Setup

See [DEVELOPMENT_GUIDE.md](./DEVELOPMENT_GUIDE.md) for complete setup instructions.

## Architecture

- [PRODUCT_VISION.md](./PRODUCT_VISION.md) — Product philosophy
- [SYSTEM_ARCHITECTURE.md](./SYSTEM_ARCHITECTURE.md) — Architecture specification
- [API_SPEC.md](./API_SPEC.md) — API contract
- [IMPLEMENTATION_RULES.md](./docs/IMPLEMENTATION_RULES.md) — Mandatory implementation rules

## Review Process

1. Every PR is reviewed against [ARCHITECTURE_CHECKLIST.md](./docs/ARCHITECTURE_CHECKLIST.md)
2. CI must pass (lint, typecheck, tests)
3. At least one maintainer approval required
4. Documentation must be updated for any API/architecture change
